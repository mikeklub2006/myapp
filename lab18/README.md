Исследование методов работы модуля OS.
Клубович Михаил, группа 401, вариант 8.

## Запуск

```bash
node os-info.js
node os-resources.js
node os-resources.js --min-free 95     # проверка предупреждения о нехватке памяти
node os-network.js
node os-monitor.js                     # Ctrl+C для выхода
node os-monitor.js --cpu-warn 5 --cpu-critical 20 --mem-warn 50   # пониженные пороги, чтобы увидеть предупреждения
```

Дополнительные параметры мониторинга: `--interval <мс>` (по умолчанию 2000), `--count <N>` (остановиться после N замеров).

## Задания

| Файл | Задание | Что делает |
|------|---------|------------|
| os-info.js | Платформа и архитектура | `platform`, `type`, `arch`, `release`, `hostname`, `uptime`, вывод по платформе |
| os-resources.js | Процессор и память | Ядра, модель, частота каждого ядра и средняя, память в ГБ и %, `loadavg`, предупреждение при < 20% свободной памяти |
| os-network.js | Сеть и пользователь | Интерфейсы с IPv4/IPv6, маскированный MAC, основной интерфейс, `userInfo()`, проверка root |
| os-monitor.js | Мониторинг | Слепок системы с меткой времени и группой, загрузка CPU по двум замерам `os.cpus()`, обновление через `\r` каждые 2 с, журнал `monitor.log` |

Формат записей в `monitor.log`:

```
[2026-11-25 09:14:09] [401] Предупреждение: высокая загрузка CPU 61.2% (порог 50%)
```

Используется только встроенный модуль `os` (плюс `fs` и `path` для журнала), внешних зависимостей нет.
В Windows `os.loadavg()` возвращает нули, а UID/GID равны -1, поэтому для них выводится пометка о недоступности.
